# Experimental Rust runtime

[Français](../rust-runtime.md)

Interrupted Rust runs are recorded in a private `goal-recovery.json` journal in the Studio data directory before the prompt is admitted. After a restart, Studio attempts each recorded eligible run once, rechecking the current session, project, goal, budget and idle queue before sending a visible service continuation. It does not replay the original user prompt or scan historical active goals. Stopped/completed runs, removed projects, archived or child sessions, cleared goals and inactive/exhausted goals are excluded. Current saved model/reasoning settings take precedence over the journal. Shutdown drains metadata writes; a corrupt journal fails closed instead of being replaced. This recovery is limited to the Rust opt-in and does not reset goal counters or authorize new work.

Native creation can acknowledge a large saved session before its goal state is restored. Recovery waits at most 30 seconds for the canonical empty placeholder to settle, then checks identity and eligibility again immediately before the prompt. A changed goal or a busy session is rejected. Run `node --test test/goal-recovery.test.mjs test/server-goal-recovery.test.mjs test/rust-goal-recovery.test.mjs` for recovery coverage. `node scripts/rust-recovery-canary.mjs ABSOLUTE_BINARY_PATH` checks adoption of 4,000 synthetic history rows with a real isolated daemon; it intercepts the prompt before inference and verifies counters remain unchanged. It does not prove completion of a model turn.

Studio keeps its JavaScript Prime Agent runtime as the default. Set `PRIME_STUDIO_RUST_CLI` to an absolute path to an official Prime Agent 0.10 executable to opt in. Rust starts a private daemon namespace for this Studio process; it never attaches to a pre-existing user daemon. Keep `PRIME_AGENT_CLI` pointed at the official Prime Agent 0.10 npm package's JavaScript metadata entry, `legacy/prime-agent/dist/bundle/cli.js`, or its nested `legacy/prime-agent` package directory. The npm package's top-level `dist` contains wrappers, not the metadata bundle. Studio uses the nested JavaScript package for the model catalogue and metadata; startup fails if it is unavailable. Install the nested package dependencies with `npm install --ignore-scripts`. The Rust executable runs agent turns. This developer opt-in is not enabled by the desktop installer.

For an initial trial, set `PRIME_AGENT_CODING_AGENT_DIR` and `PRIME_AGENT_SESSION_DIR` to dedicated directories. The Rust daemon owns its native session files. Resume is allowed only when Studio resolves an exact session file and the native create response confirms the same session and project identity. Do not point two running engines at the same session directory. The private daemon socket, worker ownership, and protocol-v7 hello are checked before commands; uncertain mutations are never retried automatically.

The Rust adapter has selected Studio integrations, not JavaScript-extension parity. This matrix describes the current opt-in path; a file or extension existing in the source tree is not proof that Rust loads or behaves like it.

| Surface | Rust opt-in behavior and limit |
| --- | --- |
| Questions, project knowledge, Roadmap | Exposed through Studio's authenticated, bounded `python_repl` bridge, initialized for each turn. Separate child Roadmap ownership is not guaranteed unless the native kernel supplies the caller's actual session ID. |
| Computer Use | Refused by the Rust run/API path; use the JavaScript runtime for this feature. |
| Meta and Muse-Code providers | The Studio JavaScript Meta provider is explicitly rejected. The JavaScript Muse-Code OAuth extension is not loaded by the Rust runtime; only models advertised by the native executable enter its catalogue. No provider parity is claimed. |
| Context extension | The JavaScript `studio-context` hook is not loaded. Rust adds its own project-image display instruction; this does not establish equivalent context-hook behavior. |
| Images and files | Image inputs can be passed on native prompt turns. Ordinary Studio file attachments are rejected before session creation. Project images can be displayed from their original project-relative paths; removed files are not archived. |
| Model catalogue and preferences | The native executable's model list is authoritative; JavaScript metadata only enriches matching IDs, and an invalid/unavailable native list fails closed. New Rust sessions receive the selected model and reasoning level in `create`. The Studio live-session adapter has no live model-switch operation; live reasoning sends `set_thinking_level` only when the daemon advertises `session_scoped_preferences`. Stock 0.10 does not advertise it, so Studio refuses the request before sending the command and cannot change global defaults through this path. Current upstream main has native session-scoped `/model` and `/effort` commands, but this Studio adapter does not yet expose both as live picker operations. |
| RPC, headless, quiescence, kernel and daemon stream | Rust uses its native daemon protocol, its `python_repl` bridge and `wait_for_headless_completion` with the RLM quiescence barrier. JavaScript loader/RPC/headless/kernel/daemon-stream hooks are not loaded by the Rust executable. The Rust wire/runtime tests cover selected adapter paths, not end-to-end parity with those hooks. |

The JavaScript runtime remains the default and its extensions are unchanged when the opt-in variable is absent.

Selected Studio subagent model/thinking defaults are refused before a Rust session is created. Native Rust subagents still exist, but this does not apply Studio's JavaScript subagent policy to them. This is an opt-in integration, not a promise that every JS extension runs in Rust.

Run `node --test test/rust-*.test.mjs` for the bounded wire/runtime/bridge tests. `node scripts/rust-native-canary.mjs ABSOLUTE_BINARY_PATH` uses an isolated temporary home and `--offline` to exercise a real daemon hello, create, attach, state and owned-session cleanup without a model call. A successful protocol smoke does not prove provider access or model-turn parity. Do not use production state or credentials for this canary.

The official 0.10 Windows binary passed connection and initial-session probes, but our saved-session cold-reopen probe failed: the previous worker still held its lease after `complete_owned_session` reported success. Current upstream main has Windows-aware lease recovery and a cold-reopen test that waits for the old worker to exit and release its lease before reopening. That upstream support does not prove that this Studio integration retries safely or that its current candidate passes a fresh Windows cold-reopen test: no such fresh proof is included here. Do not infer immediate reopen from supervisor shutdown; keep the same saved session and surface recovery while the lease drains. Linux loopback tests and protocol canaries do not establish real provider access or extension parity. This mode remains experimental.
