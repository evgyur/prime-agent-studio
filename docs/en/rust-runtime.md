# Experimental Rust runtime

[Français](../rust-runtime.md)

Studio keeps its JavaScript Prime Agent runtime as the default. Set `PRIME_STUDIO_RUST_CLI` to an absolute path to an official Prime Agent 0.10 executable to opt in. Rust starts a private daemon namespace for this Studio process; it never attaches to a pre-existing user daemon. Keep `PRIME_AGENT_CLI` pointed at the official Prime Agent 0.10 npm package's JavaScript metadata entry, `legacy/prime-agent/dist/bundle/cli.js`, or its nested `legacy/prime-agent` package directory. The npm package's top-level `dist` contains wrappers, not the metadata bundle. Studio uses the nested JavaScript package for the model catalogue and metadata; startup fails if it is unavailable. Install the nested package dependencies with `npm install --ignore-scripts`. The Rust executable runs agent turns. This developer opt-in is not enabled by the desktop installer.

For an initial trial, set `PRIME_AGENT_CODING_AGENT_DIR` and `PRIME_AGENT_SESSION_DIR` to dedicated directories. The Rust daemon owns its native session files. Resume is allowed only when Studio resolves an exact session file and the native create response confirms the same session and project identity. Do not point two running engines at the same session directory. The private daemon socket, worker ownership, and protocol-v7 hello are checked before commands; uncertain mutations are never retried automatically.

The adapter implements text/image turns, streaming events, reasoning levels, native subagents, cancellation, live queue and inspector commands, and Studio questions, knowledge and Roadmap through the Rust `python_repl` helper. The helper uses a private per-session bridge; it must be initialized each turn. These implementation paths do not establish parity with every existing JavaScript extension. The usual JS runtime and its extensions are unchanged when the opt-in variable is absent.

The following Studio-specific capabilities are not implemented by stock Rust 0.10 and are rejected when requested: Computer Use, file attachments, a selected Studio subagent model/thinking policy, the JavaScript Meta provider. Clear any selected Studio subagent defaults before a Rust turn; clearing remains available in settings. Computer Use and subagent settings remain visible for the default JS runtime; Rust requests return an explicit unsupported error. Native model availability may differ from the JS metadata catalogue, so a model shown by Studio can still be rejected by Rust at create time. This is an opt-in integration, not a promise that every JS extension runs in Rust.

Run `node --test test/rust-*.test.mjs` for the bounded wire/runtime/bridge tests. `node scripts/rust-native-canary.mjs ABSOLUTE_BINARY_PATH` uses an isolated temporary home and `--offline` to exercise a real daemon hello, create, attach, state and owned-session cleanup without a model call. A successful protocol smoke does not prove provider access or model-turn parity. Do not use production state or credentials for this canary.

Official Windows and Linux 0.10 binaries have passed connection and session probes. A loopback model-provider test completed two streamed turns and resumed the saved session on Linux. On Windows, the initial turn passed, but saved-session resume failed because the previous native worker retained its file lease after `complete_owned_session` reported success. Increasing the bounded cleanup wait does not resolve that native worker-lifecycle failure. Windows resume remains blocked pending an upstream fix; do not treat this integration as ready for ordinary Windows use. Protocol and loopback mock-provider tests do not establish real provider access or parity with all extensions. This mode remains experimental.
